# 00. 마스토돈 서버 운영을 시작하기 전에

> **검증 상태:** 공식 문서 및 운영 사례 기반 입문 안내 · **작성 기준:** 2026-10-25, Mastodon 4.7.x 계열과 Ubuntu/Docker Compose를 예시로 사용합니다. 2026-10-25에 UTM 로컬 VM에서 4.7.3 최초 설치와 주요 기능을 검증했으며, [UTM 실측 설치 기록](../labs/utm-install-v4.7.3.md)에 기록했습니다. 공개 운영용 범용 설치 절차는 별도 검증이 필요합니다.

## 이 문서에서 배울 것

Mastodon(마스토돈)을 설치한다는 것은 단순히 SNS 앱을 실행하는 것이 아니라 **인터넷에서 계속 접근 가능한 서버**를 운영한다는 뜻입니다. 다른 서버와 주고받는 ActivityPub 연합 통신, 이용자 계정, 업로드 미디어, 메일, 백업, 신고와 운영 정책까지 관리 대상이 됩니다.

### 서버를 만드는 목적부터 정하기

| 결정할 질문 | 왜 중요한가 |
| --- | --- |
| 개인용인가, 공개 커뮤니티인가? | 가입 승인·신고 처리·저장 공간·규칙이 달라집니다 |
| 예상 이용자·트래픽 규모는? | CPU/RAM보다 DB·미디어·연합 요청량이 병목이 될 수 있습니다 |
| 운영자가 장기간 관리할 수 있는가? | 업데이트, 장애 통보, 남용 신고 및 복구 책임이 생깁니다 |
| 도메인을 계속 유지할 수 있는가? | 계정 주소와 연합 서버의 식별자는 도메인에 의존합니다 |
| 메일 발송과 백업은 준비됐는가? | 가입, 계정 복구, 사고 이후 서비스 지속에 필요합니다 |

운영 부담을 감당하기 어렵다면 기존 인스턴스에 가입하거나 관리형 호스팅을 선택하는 것도 합리적입니다.

## 이 핸드북의 설치 기준

여러 설치 방식이 있지만 기본편은 **Ubuntu 서버 + Docker Engine/Compose + 외부 HTTPS 리버스 프록시** 구성을 설명합니다.

- **Docker Compose:** 앱과 데이터 서비스가 컨테이너별로 분리됩니다. 초기 구축 및 이후 이미지 기반 업데이트를 중심으로 설명합니다.
- **소스 직접 설치:** Ruby·Node.js·PostgreSQL·Redis와 서비스 관리 등을 호스트에 직접 구성합니다. [공식 소스 설치 안내](https://docs.joinmastodon.org/admin/install/)를 참고하되, **두 설치 방식의 명령을 혼용하지 마세요.**
- **커스텀 포크:** 업스트림과 달라진 코드·이미지·설정에 대한 유지보수와 보안 검증까지 직접 해야 합니다.

이 핸드북은 이해를 돕기 위해 4.7.x 예시를 사용하지만, 실제 설치 때는 **선택한 릴리스의 Compose 파일, 이미지 태그와 릴리스 노트**를 세트로 사용해야 합니다. 4.7.x가 언제나 최신 버전이라는 의미는 아닙니다.

## 예상 비용과 운영 부담

비용은 VPS/서버, 디스크 및 백업 저장소, 도메인, 외부 메일 발송, 선택적 객체 스토리지·CDN 등으로 나뉩니다. 외부 연합 서버가 많아지거나 원격 미디어 캐시가 커지면 비용이 증가할 수 있습니다. 특정 사양만 보고 수용 인원을 보장할 수는 없습니다.

기술 외에도 커뮤니티 운영 원칙, 개인정보 처리와 이용자 문의 창구, 신고·제재 절차를 정해야 합니다. 국가별 법적 의무는 서로 다르므로 현지 규정을 별도로 확인하세요.
